# Usage monitoring

Settings → Usage & alerts shows application-origin photo and backup traffic estimates. Production records one randomly selected response in twenty, weighted by twenty, into hourly aggregates. Monitoring runs after the response and failures never fail a photo download. No photo IDs, filenames, visitor identities, IP addresses, cookies or individual request URLs are stored. Only aggregate type, requests, declared response bytes, 304 responses, sample counts and 5xx errors are recorded.

These estimates exclude CDN cache hits, page/HTML traffic, database egress, uploads and storage-processing work. They are not Vercel Fast Origin Transfer, Neon consumption or an invoice. A partially downloaded response can count its full declared length. Low sample counts and large individual downloads increase uncertainty. Tracking starts with deployment; there is no historical backfill. The UI shows the number of samples, measurement time and start date. A loopback-only local test override can set `GARDEN_USAGE_SAMPLE_EVERY=1`; production always samples one in twenty.

Daily and monthly windows use UTC. The hourly request/error warnings use the current UTC clock hour. Default warning levels are 250 MB/day, 8 GB/month, 10,000 origin requests/hour and 10% 5xx errors. These are editable personal warning levels, not provider quotas or spending caps. Transfer warnings require five samples; request/error warnings require ten. Settings use optimistic version checks to avoid silently overwriting another administrator's changes.

Warnings appear in Usage & alerts and the normal admin shell. The shell checks on navigation, no more than once per minute per mounted shell. There is no unattended email, SMS or Slack integration. The monitoring screen does not poll automatically. Hourly rows older than ninety days are removed during usage reviews and occasionally while recording samples. Authentication and all photo visibility checks are unchanged.

For authoritative current usage, follow the Vercel and Neon dashboard links. [Vercel usage notifications](https://vercel.com/docs/pricing/manage-and-optimize-usage) are supplied automatically; notification preferences should be reviewed by the account owner. [Vercel anomaly alerts](https://vercel.com/docs/alerts) currently require Pro or Enterprise with Observability Plus. No paid add-on is enabled by this feature. For provider API integration later, [Neon consumption metrics](https://neon.com/docs/guides/consumption-metrics) expose consumption separately from these local estimates.
