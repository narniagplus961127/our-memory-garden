# Implementation notes

## Ticket 02 foundation

The app uses Next.js 16 App Router, React, TypeScript and Tailwind. Public surfaces use parchment; the admin shell uses sage with a 240 px desktop sidebar and equal 64 px insets. Mobile uses 28 px gutters and a collapsible admin menu. Basic text editing is intentionally temporary until ticket 04's Puck editor.

`src/lib/pages.ts` defines a serializable Puck-compatible page document. `src/lib/server/pages.ts` owns parameterized PostgreSQL queries. The browser never receives a database connection or direct data-API capability. Route handlers validate server sessions and immutable-ID administrator membership before mutation; page reads filter visibility at this server data boundary. All content responses use no-store. Text is rendered with React escaping.

`src/lib/server/auth.ts` separates managed Neon Auth from the explicit local Better Auth test provider. The managed adapter uses pinned `@neondatabase/auth/next/server` handlers and `getSession()`. The local provider uses real Better Auth sessions and PostgreSQL, not a browser identity bypass. Unknown identity IDs remain unauthorized even if the upstream provider allows them to register. The garden auth proxy only exposes sign in, sign out, session and password recovery endpoints. Cross-origin mutations are rejected against the configured canonical application origin.

Managed environment keys are `DATABASE_URL`, `AUTH_MODE=neon`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_COOKIE_SECRET` and `NEXT_PUBLIC_APP_URL`. The older local fixture names AUTH_PROVIDER/NEXT_PUBLIC_SITE_URL are accepted only as configuration aliases. The cookie secret must be at least 32 random characters. Local fixtures are not used for hosted provisioning.

## Ticket 03 visibility and homepage

`garden_settings` stores one homepage reference. Its selection trigger locks and validates an available public page; page triggers protect that active page from becoming private, entering trash or being deleted. The application also gives a clear conflict response when an administrator tries to hide the homepage. The first authenticated administrator layout visit initializes a normal public homepage if none is configured. Initialization and selection share a transaction advisory lock to prevent competing initial homepages.

`src/lib/server/homepage.ts` is the server-only homepage boundary. `/api/homepage` returns only the public, non-trashed homepage; its mutation requires the same session, administrator and origin checks as page editing. The ordinary editor submits text and visibility together under a single page version. Both `/` and `/p/[id]` read current saved state dynamically. `GardenPage.is_homepage` is a derived marker, not an editable content property.

The Homepage settings page follows existing desktop/mobile FigCraft frames 955/959: current public page, a public-page picker, the semantic Choose as homepage action, and deletion-protection copy. It reuses the approved fields, cards, colors and responsive gutters. No separate Save, Publish or Preview control was introduced. The current text renderer and basic editor remain temporary until ticket 04's Puck slice.

Eight desktop/mobile browser journeys and five API/database checks passed locally. Ticket 03 adds coverage for immediate visibility transitions, homepage selection and editing, and rejection of hiding/trashing/deleting the current homepage directly at the database boundary. Hosted migration/application verification is separate; apply `db/migrations/0002-homepage.sql` through the checked-in runner before deploying this slice. The runner prefers nonempty `DIRECT_DATABASE_URL` for hosted migrations and falls back to `DATABASE_URL` for local development. Runtime requests continue to use the pooled `DATABASE_URL`.

## Ticket 04 Puck pages and templates

Puck is pinned to 0.23.0. Its composed editor replaces BasicPageEditor with garden-owned content/settings panels and a live iframe canvas. The workspace has no separate Save, Publish, Preview, undo or redo actions. It supports text, banner, placeholder image, external button, section and columns blocks; public pages and the homepage use the same gardenConfig through Puck's server Render. Sections and columns use slot fields, with recursive validation of every descendant at the authenticated page API.

The palette provides desktop drag handles alongside touch Add buttons. Explicit insertion targets include Page, each section content slot, and both columns, including empty slots. Selected blocks can move among siblings, duplicate with independent descendants, or be removed. Removing a top-level block clears selection; removing a nested block selects its surviving parent. Puck's root is never passed to the block selector API. The editor bypasses the dashboard sidebar to preserve the approved dedicated workspace.

Blank, story and journal templates generate fresh IDs recursively per page. The desktop/mobile controls set the actual iframe to 1280/390 px, so shared CSS media queries respond to canvas size. Mobile opens full-width settings under the live canvas and uses labelled 44 px controls. The automatic saver debounces changes, serializes writes under the current page version and follows an in-flight request with the latest queued snapshot. Failed writes retain current edits with Retry save. Ticket 09 must add durable device recovery and conflict handling; no such guarantees are implied here.

Validation passed: production build, TypeScript, formatting, six local service checks, and a full browser run with 17 passed/one intentional mobile drag skip. The skip uses the tested mobile tap/move alternative. A new browser error assertion caught a root-selection exception after removal; the fixed affected journey passed on desktop and mobile. Browser coverage verifies nested tap insertion, sibling selection, duplication/removal, actual iframe widths and responsive columns, template independence, desktop cross-column drag with refresh persistence, newer edits during a slow save, failure/retry, public block rendering, homepage editing and privacy. Inspected screenshots remain in ignored work/ticket04-evidence/. Hosted Neon Auth/deployment verification stays in ticket 13.

Image blocks remain placeholders until ticket 05. Buttons accept http/https external URLs; ticket 08 supplies stable internal references and navigation. Browser tests may use PORT and PLAYWRIGHT_BASE_URL to isolate local servers; the configured application/auth origin must match that server.

## Ticket 05 secure photos

`0005-media.sql` adds shared photo records and `garden_photo_ids(jsonb)`, a recursive reference scanner for nested image `photoId`, gallery `photoIds` / `photos[].photoId`, and cover/sharing-cover keys. Media accessibility derives from current live public page references at request time, rather than cached counters or bucket ACL changes. `photoUsages()` includes current trashed-page references with a deleted marker; trash does not grant public access. Future deletion must also inspect `page_versions.snapshot` using the same scanner, and coordinate photo row locks with page-reference writes. Ticket 05 has no photo-deletion endpoint, so it cannot remove retained history/trash media.

The authenticated upload API creates a 15-minute presigned PUT for one random private staging key, signing the declared Content-Length. Browser file bytes bypass the application's request body, preserving support for photos above Vercel's 4.5 MB request limit. Finalization locks the photo record, reads a bounded snapshot, checks actual byte length, decodes supported still JPEG/PNG/WebP up to 25 MiB and 40 megapixels, auto-orients and re-encodes a display WebP within 2560 × 2560. Sharp's default output strips EXIF/XMP/ICC metadata. The immutable original and display keys are server-written; a replayed staging PUT cannot replace ready media. A record becomes ready only after both writes succeed; repeating finalization returns the completed photo.

Both buckets stay private. `/api/media/[id]/display` rechecks current public usage or an allowlisted administrator session for every request, and streams bytes with private/no-store headers. `/original` always requires administrator access and streams an attachment, avoiding a buffered response body above the hosting limit. These gateway URLs deliberately bypass Next Image optimization and permanent signed display URLs so the final public reference's removal immediately denies subsequent anonymous requests. Previously downloaded bytes cannot be recalled.

The shared library and Puck image field use real upload/finalization results. Each file has queued/uploading/processing/ready/error feedback, measured transfer progress, independent retry and remove-failed controls. Photo details show current usage, public/private accessibility, measured sizes and protected original download. In-use deletion is disabled; unused deletion and export are ticket 11. Dialog Escape/close return focus to its trigger. Library name filtering currently runs on the loaded library; ticket 11 can add pagination/server search as needed.

Validation: eleven local API tests pass, including five media scenarios using real PostgreSQL, Better Auth and S3-compatible storage. They establish both administrator access, a real signed outsider's denial, corrupt/SVG/size mismatch rejection, exact retained originals, resized metadata-free display output, staging replay resistance, nested/shared public usage and immediate privacy transitions. Desktop/mobile browser journeys cover file failure/retry, upload, details, keyboard close/focus, Puck selection/reuse, refresh persistence, anonymous public rendering and in-use safeguarding. Production build, typecheck and formatting are checked before delivery. Screenshots are ignored under `work/media-desktop.png` and `work/media-mobile.png`.

Hosted Neon interoperability was separately checked against both actual Singapore private buckets: signed put/get, presigned PUT and unsigned GET denied with 403; only owned temporary smoke objects were removed. `scripts/configure-media-cors.mjs` preserves existing rules and adds the exact canonical application origin for browser PUT. Its production-origin preflight succeeds; the provider responds with Allow-Origin `*` despite storing an exact-origin bucket rule. Presigned browser uploads use no credentials, while the signature still grants only one temporary PUT. Hosted managed-auth browser upload and original downloads above 4.5 MB remain deployment checks in ticket 13.

Production maintenance can use `scripts/cleanup-media-staging.mjs`: dry-run by default, explicit `--apply`, at most 100 pending uploads expired for more than one hour per invocation, row locking with SKIP LOCKED, strict validation of recorded server-generated staging keys and an audit marker to advance subsequent batches. It only deletes those staging objects; it never deletes ready originals/display copies or page/version content. A real local CLI/API/S3 test verifies dry-run preservation, expired-pending cleanup and ready-media preservation. Ticket 13 owns scheduling/manual production operation. Successful finalization separately removes its staging key best-effort; staging replay after readiness and partial non-ready output cleanup remain a follow-up for retention maintenance. Neon lifecycle configuration alone does not enforce expiry. The local `s3rver` fixture is development-only and listens on loopback; its transitive busboy/dicer/XML-parser advisories do not enter the production runtime (`npm audit --omit=dev` retains the existing seven low advisories).
