## Shared interaction rules

Ticket 27 replaces inline recovery confirmation cards with centred native popup dialogs, bounded to the viewport with scrollable content and sticky actions. Cancel/Escape dismiss safely and return focus; request progress blocks dismissal. Failed actions retain their warnings and retry/reload controls inside the popup. Routine editor notices and save errors use fixed bottom-right toasts; mobile uses 16 px side/safe-area clearance. Error toasts persist with Retry save; short notices expire after six seconds, paused for mouse/keyboard interaction. Persistent recovery/conflict decisions stay in their existing review surface. Native FigCraft frames are not redrawn for this owner-requested refinement.

Ticket 26 sets root/body text to 14 px using `--body-font-size`, shared with form controls. Standard button text inherits it, and administration links match it. Heading sizes and explicitly authored font sizes retain their own hierarchy. This supersedes the original 16 px body default.

- Settings changes update the live canvas and autosave; show Autosaving… / Saved / Unsaved · Retry from actual persistence. No Save, Publish, Preview or Undo/Redo controls. Opening or closing a panel and switching device width do not change content.
- Desktop editor owns its toolbar and a 352 px inspector track (ticket 24 replaces the original 320 px panel). White rounded inspector/workspace surfaces, subtle section dividers and forest accents follow the owner's Klaviyo reference. Mobile opens a full-width settings surface below the compact live canvas; Close returns to canvas without discarding edits. Long forms scroll. Touch actions are at least 44 px high.
- Admin desktop keeps its 240 px sidebar, equal 64 px sidebar insets and content at x=304. Mobile keeps 28 px gutters. Public/rendered blocks use warm paper; admin surfaces use sage. Arial/Georgia, approved forest/sage/clay palette and placeholder photos only.
- Button and text destinations share Garden page / External URL controls. Use page IDs for internal references; validate URL and address fields inline while retaining entered values. New empty fields use their labels rather than relying on placeholders.
- Gallery viewer uses the existing Desktop / Gallery and Mobile / Gallery references for image presentation. Functional Previous / Next / Close, keyboard escape/arrows, focus return and optional captions require application verification.
- These are static state references. Back/menu links return to existing frames; status labels and example fields do not simulate authentication, persistence, upload, export or security. Newly illustrated primary actions require implementation, not prototype-click acceptance.

## Image links and alignment (ticket 29)

Image Styles includes an optional Link group with None, Garden page and External URL destinations. Saved website images are linked; captions remain separate. Alignment controls include Left, Centre and Right for blocks and inline paragraphs.

## Section-first layouts (ticket 30)

Blank canvas → Add Section → add blocks or Columns inside it. Section has its own Styles groups for background image, content background (Auto/Custom/None), Section colour, border, spacing and vertical column alignment. Root drag accepts Sections; child slots reject Sections; Add/Move targets follow the same hierarchy. Existing root blocks remain compatible. Desktop/mobile implementation screenshots and browser checks are recorded in ticket 30; these incremental owner requests supersede the older native frame's unrestricted root insertion.

## Navigation dragging (ticket 31)

Navigation cards have a 44 px grip before the label/destination and compact Edit/Remove actions with full accessible names. Mouse/touch dragging shows a floating label, dims the moved subtree and highlights the sibling insertion point; dragging near viewport edges scrolls the page. Drop saves the sibling order once. Parent item still controls nesting. Keyboard: Space/Enter picks up, arrows or Home/End choose the position, Space/Enter drops, Escape cancels, Tab leaves without moving. Announce pickup/position/drop/cancellation, retain focus and keep save/retry feedback. Navigation arrow buttons are removed; page-editor block move alternatives are unaffected. [Desktop dragging](evidence/ticket31/navigation-dragging-desktop.png), [mobile](evidence/ticket31/navigation-mobile.png). This incremental application reference supersedes the older static navigation arrows.

## Navigation form pages and confirmation (ticket 34)

The menu list fills the administration content area. Add menu item opens `/admin/navigation/new`; each pencil opens `/admin/navigation/[id]/edit`. Both reuse the admin shell, with a single-column form containing Menu label, Destination type, Garden page or External web address, and Parent item. Back/Cancel return to the list without writing. Submit saves and returns to the updated list. Inputs remain after failure; a changed item requires an explicit review of saved values. Other items' concurrent updates are preserved.

The trash icon opens the shared centred confirmation popup. It names the selected item, counts all nested items to be removed and states that pages/content are kept. Cancel is initially focused; Escape cancels, and cancelling returns focus to the trash icon. During removal, both actions are disabled and Escape cannot dismiss the pending request. Errors and retry stay in the popup; Review saved menu reloads without deleting. After success, focus moves to Your menu. Keep 44 px action targets and responsive fields on mobile. Native FigCraft frames have not been redrawn for this owner-requested increment; these application states supersede the earlier right-side form.
